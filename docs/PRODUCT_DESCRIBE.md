# UniConf 当前产品能力

本文档描述仓库当前已经实现的产品，不是需求池或路线图。若本文与代码不一致，以以下实现为准：

- 导出格式与客户端能力：`packages/shared/src/index.ts`
- 协议注册表：`packages/types/src/protocols.ts`
- 数据结构：`apps/worker/migrations/0001_initial_schema.sql`
- 页面入口：`apps/web/src/app/router.tsx`
- API：`apps/worker/src/index.ts` 与 `apps/worker/src/routes/`

## 产品定位

UniConf 是一个单管理员、自托管的代理配置管理服务。管理员可以建立多个相互隔离的配置空间，分别维护自己或朋友的配置；每个空间将多个订阅和手动节点汇总后，在同一套节点组与分流模型上生成不同客户端配置。

核心原则：

1. 数据只维护一份，目标客户端配置由 Worker 按需生成。
2. 系统提供一套可直接工作的默认节点池、出口、分流组、规则集和导出档案。
3. 客户端能力不相同时，优先使用原生来源或安全转换；不能保持语义时明确省略或阻断。
4. 配置空间只是管理员的数据隔离单元，不是账号、团队或权限系统；配置使用者通过公开订阅 Token 获取结果。

## 使用流程

1. 选择现有配置空间，或为一套真正独立的配置创建新空间。
2. 添加一个或多个订阅链接，或导入已有配置。
3. 在节点页确认解析结果、地区和启用状态。
4. 使用系统自动节点组，或创建带过滤、重命名、去重和排序规则的节点组。
5. 选择业务分流场景并调整各业务组的默认出口。
6. 按需增加手动规则、补充远程规则集或覆盖规则集目标。
7. 在预览中检查目标客户端的结构、引用、协议和规则集兼容性。
8. 下载配置，或把公开订阅链接添加到客户端。

同一套节点与分流仅需适配不同客户端时，应在同一配置空间建立多个导出档案；只有订阅、节点、分流或 DNS 确实需要独立维护时才创建新空间。

首次缺少可用节点时，概览页可以触发全局新手引导；引导状态只在概览页判断，不在每个页面重复初始化。

## 订阅源与导入

### 远程订阅

订阅源支持 URL、自动/指定格式、自定义 User-Agent、独立刷新间隔、启停、立即刷新和流量信息。名称为空时会从订阅 URL 推导，并识别 URL 中的 `name` 参数。

全局自动刷新默认开启，默认间隔为 240 分钟。单个来源的间隔为 `0` 时继承全局值。Worker 的五分钟 Cron 只选择已经到期的来源刷新，不代表每五分钟下载全部订阅。

关闭订阅源后，其节点不会参与节点组、分流出口和导出。

### 配置导入

可粘贴或上传：

- Clash/Mihomo YAML
- sing-box JSON
- Base64 节点订阅
- 原始节点 URI 行

Clash/Mihomo 规则-only 文档也可导入。导入预览会区分新增、已存在、冲突和无法映射的节点、手动规则与 HTTP 规则提供器。DNS 和客户端专属配置不会被静默改写。

配置内容限制为 4 MiB UTF-8。导入记录只保存摘要和撤销所需的非敏感路由字段，不复制节点凭据。节点阶段和规则阶段可以独立失败并独立重试；成功导入可撤销。

## 节点

当前协议注册表覆盖：

`ss`、`ssr`、`vmess`、`vless`、`trojan`、`hysteria`、`hysteria2`、`tuic`、`anytls`、`naive`、`wireguard`、`socks5`、`http`、`https`、`ssh`、`shadowtls`。

协议能被录入或解析，不等于每个导出客户端都支持它。导出预览使用客户端能力注册表判断最终可序列化范围。

手动节点支持 URI 识别和协议字段表单。国家/地区可以手动选择，也会从名称中的旗帜、国家代码和常见地区名称推断；数据库只保留一个展示名称和一个 ISO 两位代码，不维护重复的第二套地区概念。

节点页支持名称、服务器、来源和地区搜索，以及协议、地区、来源、启用状态筛选。批量启停单次最多 500 个节点。

## 节点组

节点组用于产生一个确定的节点集合，可组合：

- 一个或多个订阅源
- 明确选择的节点
- 名称、服务器、协议、国家/地区、标签和来源过滤
- 替换、正则、前后缀、去 Emoji、国家名标准化、自动编号
- 按名称、国家、来源、协议或手动顺序排序
- 按名称、服务器端口、协议与服务器端口或完整配置去重

系统维护“默认节点池”，默认排除 `high-multiplier` 标签节点。

自动节点组默认开启，默认生成 `url-test` 类型；也可启用 `select` 和 `fallback`。用户可以选择具体国家/地区和标签候选、是否显示旗帜，以及是否导入启用订阅源提供的节点组。

## 分流方案

### 固定基础目标

- `PROXY`：默认代理目标
- `DIRECT`：直连
- `REJECT`：拒绝

### 固定全局节点出口

- 全部节点
- 节点选择
- 自动选择
- 故障切换

这些出口使用系统维护的默认节点池。关闭自动国家/标签节点组不会删除基础目标和全局节点出口。

### 业务分流场景

场景可以叠加，场景决定系统启用哪些业务策略组：

| 场景       | 业务组                                   |
| ---------- | ---------------------------------------- |
| AI 与开发  | AI、GitHub、Google、Microsoft、Developer |
| 流媒体     | Streaming                                |
| 通讯与社交 | Social                                   |
| 游戏       | Gaming                                   |
| 加密货币   | Crypto                                   |
| 券商       | Broker                                   |
| 网络诊断   | Speedtest                                |
| 平台服务   | Apple、Microsoft、Google                 |

默认启用 AI 与开发、流媒体和网络诊断。共享业务组会去重。业务组默认包含可用的基础出口、全局节点出口和自动节点组，用户主要调整“默认出口”；Speedtest 默认优先 DIRECT。

用户也可以新增、编辑、排序和删除非内置策略组。系统会阻止产生悬空引用或策略组循环。

### 默认代理 / 默认直连

`unmatchedTrafficPolicy` 控制基础分流模型：

- `proxy`（页面显示“默认代理”）：系统启用明确的私网/国内直连规则，其余未被更具体规则命中的流量走代理兜底。
- `direct`（页面显示“默认直连”）：系统启用明确的代理规则，其余未被更具体规则命中的流量直连。

它不只修改最后一条 MATCH，还会影响哪些系统规则集处于活动状态。AI、Streaming、Microsoft 等业务规则仍按各自目标组处理。

## 规则

### 手动规则

支持域名、域名后缀/关键字/正则、IPv4/IPv6 CIDR、ASN、GeoIP、GeoSite、进程、端口、来源 IP、协议、网络、入站类型、规则集、脚本和 MATCH 等类型。

规则按全局顺序从上到下匹配。页面支持搜索、筛选、排序、批量创建和批量启停。`no-resolve` 只在目标客户端和规则类型均能表达时输出。

### 远程规则集

远程规则集保存默认来源、格式、行为、目标组、可选目标覆盖、更新间隔和目标客户端原生来源。系统规则集不能修改其规范名称和默认来源，但可以：

- 启停
- 设置目标覆盖
- 添加目标客户端原生来源

补充规则集可从 QuixoticHeart 完整目录选择，也可直接填写 URL。订阅源自身声明的 HTTP rule-provider 可以随配置导入并保持来源关联。

QuixoticHeart 与 Broker 的目录映射位于根目录 `resources/rule-set-catalogs/`。部署前脚本从第三方仓库生成快照；运行时使用内置快照启动，并通过 KV 定期刷新目录。系统默认只自动创建标为 `foundation` 或 `scenario` 的子集，目录中的 `optional` 项只供用户选择。

### 格式识别和转换

`@uni-conf/rule-set` 负责文本/YAML/JSON、Mihomo MRS 和 sing-box SRS 的识别、检查与转换。

转换策略：

- `compatible`：保留能够准确转换的规则，报告被省略的指令。
- `strict`：只要需要的转换存在被省略规则，就阻止下载和订阅交付。

客户端没有某条本地规则指令时，不会仅因名字相似而原样输出。例如 Surge 和 Loon 当前导出器不会输出 `GEOSITE`；应改用目标客户端原生远程规则集。

## DNS

系统统一保存两类 DNS 意图：

- 解析路由：单一上游或国内/国外分流
- 额外真实 IP 域名

完整配置导出器根据客户端自身 DNS 结构转换该意图。节点订阅不包含 DNS。QuixoticHeart 的 fake-ip-filter 作为系统维护的真实 IP 例外来源：

- Mihomo 使用 MRS rule-provider
- sing-box 使用 SRS rule-set
- 需要内联列表的客户端使用 KV 中的刷新结果，失败时回退到代码内快照

Mihomo 配置同时包含 GeoIP、GeoSite、Country MMDB 和 ASN 下载地址，并开启 24 小时自动更新。这些 Mihomo 专属字段不会附加到 Clash 或 Stash 导出。

## 导出

系统自动创建一个不可删除的默认导出档案。默认档案覆盖全部当前数据，格式由实际请求决定，只允许暂停/恢复；高级档案可以固定格式并选择节点组、策略组、手动规则和远程规则集范围。

高级档案可继承全局规则集转换策略，或设置自己的 `compatible` / `strict` 策略。Token 可以重置；暂停档案后，公开链接返回不可缓存的 404，恢复后原 Token 继续生效。

完整配置格式：

- Mihomo
- Clash
- sing-box
- Loon
- Surge
- Shadowrocket
- Quantumult X
- Stash
- Egern

节点订阅格式：

- Base64 URI
- 明文 URI

预览、下载和公开订阅复用同一套数据构建、规则集预检、生成器和结构校验。预览会返回：

- 当前客户端能力版本
- 非阻断兼容性提示
- 阻断就绪度
- 规则集转换结果
- 最终产物结构校验结果

公开路径：

```text
/sub/{token}/mihomo.yaml
/sub/{token}/clash.yaml
/sub/{token}/singbox.json
/sub/{token}/loon.conf
/sub/{token}/surge.conf
/sub/{token}/shadowrocket.conf
/sub/{token}/quantumultx.conf
/sub/{token}/stash.yaml
/sub/{token}/egern.yaml
/sub/{token}/nodes.txt
/sub/{token}/nodes-raw.txt
```

## 设置与数据

设置页维护语言、主题、基础分流方式、业务场景、出口偏好、节点命名、DNS、兼容性提示、规则集转换策略、自动刷新和自动节点组。

数据管理支持：

- 导出备份
- 在写入前校验备份结构和引用
- 清空配置数据
- 恢复受支持版本的备份

备份包含节点凭据，应视为秘密。

## 安全与边界

- 生产环境要求 `API_KEY` 和 `ALLOWED_ORIGIN`
- `/api/health` 与 `/api/ready` 公开；其他 `/api/*` 可由 Bearer Token 保护
- 公开订阅由每个导出档案的 Token 保护
- 上游请求拒绝凭据 URL、localhost、私网/保留地址和不安全重定向
- 所有响应附带请求 ID；公开订阅和下载错误还提供稳定错误代码
- 当前没有账户、团队、分享权限和审计后台
